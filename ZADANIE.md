## Дефекты, которые надо устранить

1. **Кнопки паузы не работают.** В qBittorrent 5.x маршруты `/api/v2/torrents/pause` и `/resume` удалены, отвечают 404. Работают `/torrents/stop` и `/torrents/start`. Сейчас `QbittorrentManager.pause/resume/pause_all/resume_all` (`src/client_manager/qbittorrent_manager/qbittorrent_manager.py`) ходят в мёртвые методы — вся пауза/возобновление мертвы.
2. **Фильтр `paused` тоже мёртв.** `GET /api/v2/torrents/info?filter=paused` в 5.3 возвращает **все** торренты (61 из 61). Остановленные отдаёт `filter=stopped` (сейчас 2).
3. **Разметка противоречива.** `ParseMode.MARKDOWN` (legacy) при `escape_markdown()`, который экранирует символы по правилам MarkdownV2 — в названиях торрентов вылезают лишние `\`.
4. **ETA по-английски**: `convert_eta` возвращает `str(datetime.timedelta(...))` → `1 day, 2:03:04`.
5. **Русификация кривая** (см. раздел про локали).
6. **Тестов нет вообще.** Их надо завести.

## Задача 4. Переименование (два разных действия)

Проверено по исходникам qBittorrent 5.3: `POST /api/v2/torrents/rename` (`hash`, `name`) вызывает `TorrentImpl::setName` и меняет **только название торрента в клиенте**, файлы и папки на диске не переименовываются. Диск меняют только:
- `POST /api/v2/torrents/renameFolder` (`hash`, `oldPath`, `newPath`)
- `POST /api/v2/torrents/renameFile` (`hash`, `oldPath`, `newPath`)
Оба возвращают 409 при недопустимых символах в имени файла/папки.

В карточке торрента (`src/bot/handlers/callbacks/torrent_info.py`) добавить кнопку `✏️ Переименовать`, она открывает подменю:
1. **`📛 Название торрента`** — бот просит новое название текстом, предупреждает: «имя изменится только в клиенте, файлы на диске останутся как есть». Ввод через redis-механизм `action:{user_id}` (см. ниже). Сохранение → `/torrents/rename`.
2. **`📁 Папка/файл на диске`** — получить `GET /api/v2/torrents/files?hash=<hash>`, построить список уникальных путей верхнего уровня (первый компонент пути). Если у торрента один файл в корне (нет общей папки) — показать сам файл. Выбранный путь → бот просит новое имя (только имя, не путь) → `/torrents/renameFolder` или `/torrents/renameFile` (в зависимости от того, папка это или файл), при этом `oldPath` = выбранный путь, `newPath` = тот же путь с заменённым последним компонентом. После успеха — сообщение об успехе и обновлённая карточка.

Ввод текста. В боте уже есть механизм: `redis.set(f"action:{user_id}", "<тип>#<payload>")`, чтение — в `src/bot/handlers/on_message.py`. Использовать его же: `rename_torrent#<hash>`, `rename_path#<hash>|<oldPath>`. Не вводить второй механизм (FSM-состояния) — в проекте redis-подход уже принят, второй способ раздвоит логику. Добавить ветку «отмена» (`/cancel` или текст `Отмена`) на всех шагах ввода.

Ограничения:
- Не переименовывать торрент, который сейчас качает/проверяет (`downloading`, `checking*`, `moving`) — вернуть понятный отказ: сначала остановить.
- Имя валидировать на клиенте: непустое, без `\ / : * ? " < > |` и управляющих символов, длина ≤ 255.
- Для остальных языков строки тоже добавить в .po (перевести на en обязательно, остальные — английским текстом как fallback).
